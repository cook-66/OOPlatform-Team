# D3/D4 数据工程实现说明

## 1. 职责与处理流程

D3 只负责原始数据识别、VOC/COCO/YOLO 转换、划分、物化、数据集 YAML、manifest 和 transform 印章。D4 只读取 D3 产物，执行 16 项检查并写报告与 validate 印章；本次没有修改训练、推理、Web 或 LLM 模块。

流程为：`data/raw/<dataset>` → 自动识别源目录 → 转为 YOLO 标签 → 校验图片/标签集合 → 生成或保留 split → 写 manifest → 物化到 `data/processed` → 写 YAML 和 transform 印章 → D4 建快照并执行检查 → 写 validate 印章。

## 2. 关键实现

- `apps/platform/src/od_platform/data_pipeline/source_layout.py:58`：`discover_source_layout` 识别普通 `images + annotations|labels`、压缩包多层外壳、Roboflow `train/valid/test`、`imgs/{train,val,test} + instances_*.json` 及 JODD 风格 `coco_*_data`。多候选或同 stem 冲突时拒绝猜测。
- `apps/platform/src/od_platform/data_pipeline/orchestrator.py:137`：`DatasetPipeline._execute` 串联转换、严格配对、划分、manifest、物化和盖章。合法负样本必须使用空 YOLO 标签或 COCO `images` 声明，缺失标签不能被静默当作负样本。
- `apps/platform/src/od_platform/data_pipeline/split/strategies/preserve_source.py`：`preserve_source` 保留上游官方 train/val/test，`valid` 统一映射为 `val`。
- `apps/platform/src/od_platform/common/lineage.py:44`：数据指纹从原来的“stem + 标签哈希”升级为“stem + 图片哈希 + 标签哈希”；旧 manifest 未带图片哈希时仍按旧配方读取。
- `apps/platform/src/od_platform/data_validation/checks/image_readability.py:11`：使用 Pillow 解码验证每张图片，损坏图片为 ERROR。
- `apps/platform/src/od_platform/data_validation/checks/manifest_lineage.py:24`：逐样本检查图片/标签哈希、split 移动、文件缺失。
- `apps/platform/src/od_platform/data_validation/identity.py:106`：按 D4 文档分级执行门禁。PASS、INFO、WARNING 可继续且保留原始严重度；ERROR、缺章、无效章、未知严重度、数据或契约指纹不一致拒绝。`--skip-validate` 原有显式语义保留，但不能绕过无效身份。

## 3. 原问题与修复结果

1. 压缩包解压后多一层目录或目录名不同：原实现写死 `raw/<name>/images`，现由唯一候选发现器解析；歧义时输出候选位置并停止。
2. Brackish 官方划分被重新随机划分：新增 `preserve_source`，不再把原 test 样本混入 train。
3. 图片内容不进入指纹：manifest 0.5 增加图片 SHA-256，图片损坏、替换或缺失会被 D4 拦截。
4. COCO/YOLO/VOC 配对不完整会被交集运算静默丢样本：现要求一一配对并给出缺图片、缺标签清单。
5. D4 INFO 被误当成训练失败：门禁按文档严重度语义处理，不把 INFO/WARNING 篡改为 PASS。
6. 测试依赖开发者本机绝对路径：测试夹具会检查 YAML、processed 和 manifest，缺失或版本过旧时生成有效图片并重建。

## 6. 答辩常见问题

**为什么 Brackish 是 INFO 还允许训练？**  D4 文档定义 INFO 为非阻断提示，WARNING 也可训练但建议处理，只有 ERROR 阻断。空标签是官方声明的无目标背景样本，删除它们会改变数据分布。

**如何防止数据泄漏？**  已有官方 split 时用 `preserve_source`；D4 再以 stem 检查跨 split 重复。Brackish 此次没有重新随机划分。

**指纹保护什么？**  data fingerprint 标识图片与标签内容集合；contract fingerprint 还加入 split、类别、策略和比例。换图、改标签或移动 split 都会留下不同证据。

**为什么不自动选多个候选目录中的一个？**  猜错目录会把图片和错误标签配对，产生难以发现的数据污染；因此歧义必须明确报错。
