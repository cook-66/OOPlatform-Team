# Web 工程师答辩指南

## 1. 一句话定位

我负责把算法、LLM、数据三块能力落成一个**可演示、可追溯、可计费**的 Web 平台：Django 做接口与持久化，Vue3 + Tailwind 做五模块单页控制台，ECharts 做数据可视化，并承担推理性能、视频兼容、并发一致性这些"工程收口"问题。

不要把自己讲成"写页面的"，要讲成"**系统集成者 + 工程问题解决者**"。老师最容易给分的是：真实数据、真实指标、真实踩坑与修复。

## 3. 现场演示顺序（按此顺序最稳）

1. 打开首页，停在"项目介绍"，用 20 秒讲技术栈与闭环。
2. 切"数据理解"：指出 24 类真实统计、Lure 最多、Metal Rod 为 0（**主动说出**，显得诚实且懂数据）。
3. 切"模型训练"：真实 mAP50 89.7%、100 轮、真实训练曲线图。
4. 切"模型推理"：
   - 上传一张**事先准备好的、模型能识别的图**（不要现场赌网图）；
   - 置信度保持 0.25 推理 → 出框 → 触发 LLM 解释 → 展示"本次花费"和 tokens；
   - 拖动滑块到 0.7/0.9 再点一次推理（**不用重新选文件**）→ 框减少/消失，证明阈值真实生效；
   - 再上传一段**短**视频（建议 3–5 秒、已提前验证可播放）→ 展示进度提示与结果视频。
5. 切"仪表盘大屏"：KPI、7 天折线、类别环形图、历史表格。
6. 在历史表格点"查看详情"→ 弹窗展示原图/结果图/解释/花费，证明持久化与可追溯。

**演示前必须做的准备**
- 提前跑一遍全流程，确保 `media/results/` 里有可播放的 H.264 视频；
- 准备 3 张图：1 张必然检出、1 张低置信度、1 张无关图（用于解释"不确定就不胡说"）；
- 准备 1 段短视频（<10 秒），确认浏览器能直接播；
- 若现场网络不稳，提前截图/录屏兜底（Vue、Tailwind、ECharts 都是 CDN）。

## 4. 必须讲清的技术点（附可核验事实）

### 4.1 架构与接口
- 单页 + 五模块，Vue3 只负责视图切换，推理逻辑保留原生 JS（fetch/FormData），避免框架与业务耦合过深。
- 后端接口：`/api/infer/`、`/api/explain/`、`/api/history/`、`/api/record/<id>/`、`/api/today-cost/`、`/api/trend/`。
- 持久化：`InferenceRecord`（原图、结果、类别、置信度、解释、tokens、花费），迁移到 0003。

### 4.2 推理性能（最容易被追问，也最出彩）
- 问题：每次请求都新建 `YOLO()`，单张图 20 秒级。
- 方案：进程内全局单例 + 双重检查锁 + 启动预热线程 + 推理串行锁（ultralytics 实例不保证线程安全）。
- 结果：首次 18.22 s，二次 **0.12 s**，单帧推理约 0.07 s。
- 诚实补充：多 worker 部署时每个进程各有一份模型，需要改 Redis/共享推理服务；当前是单进程教学部署。

### 4.3 视频双模态
- 上传按 `content_type` + 扩展名判定；图片走单帧，视频逐帧推理后合成。
- 编码从 `mp4v` 换 `avc1`（H.264）：`mp4v` 是 MPEG-4 Part 2，Chrome/Safari 的 `<video>` 不支持，表现为"能生成但黑屏"。
- 写后回读校验帧数，避免 `isOpened()` 假成功留下坏文件。
- 前端 `onerror` 降级：不能播就显示提示 + 下载按钮，并做 `src` 重置防止事件串台。
- 诚实补充：视频是逐帧 CPU 推理，10 秒 30fps 约十几秒，属于算力限制，不是加载问题。

### 4.4 并发一致性
- 解释接口必须用前端回传的 `record_id` 精确更新记录；只有缺 `record_id` 才回退"最近一条"。多人同时操作不会写串。
- 这是"看起来能用"和"数据可信"的分界线，值得重点讲。

### 4.5 LLM 与成本
- Prompt 防呆：低置信度/无目标时明确说"无法确认"，禁止臆测场景（现场可用一张无关图演示）。
- 返回结构含 `text / cost / tokens`，入库后按本地时区汇总"今日花费/今日 Token"。
- 示例：一条解释 475 tokens，约 ¥0.00079。

### 4.6 数据与指标口径（务必统一）
- 数据集：9,663 图、24 类、15,976 个标注实例；训练划分为 7,730 / 966 / 967（平台 80/10/10 重划分，非原始 COCO 划分）。
- 训练：mAP50 **89.7%（best.pt）**，末轮 86.2%，第 34 轮最高 90.48%；数据取自 `runs/training/20261026-091721/`。
- 元数据：`Metal Rod` 标注实例为 0，该类指标不可信，答辩时主动说明而不是掩盖。
- 7 天趋势是**真实按日聚合**，目前只有今天有数据，其余为 0；不要为了好看编曲线。

## 5. 高频提问与参考回答

**Q1：为什么不用 Vue CLI/React + 前后端分离？**
A：课程部署环境只有 Django 单服务，CDN 引入 Vue 能以最低成本获得组件化与响应式视图切换；接口本身已 REST 化，未来换独立前端只需改静态托管，不需要改后端。

**Q2：模型怎么加载？会不会每次请求都加载？**
A：全局单例，首请求或启动预热时加载一次，之后复用；有锁保证并发安全。给出 18.2s→0.12s 的实测。

**Q3：视频为什么黑屏？怎么修的？**
A：编码兼容问题，`mp4v` 浏览器不支持；改 H.264 并加写后校验，前端再加播放失败降级下载。

**Q4：LLM 会不会胡说？**
A：有防呆 Prompt + 空检测直接短路 + 解释文本与检测结果同框展示；示例中低置信度会明确回答"无法确认"。

**Q5：费用怎么算的？准吗？**
A：按接口返回的 token 用量与单价估算，属于"预估花费"，入库后按天汇总；不是真实账单，措辞上避免说"精确计费"。

**Q6：为什么趋势图全是 0？是不是没做？**
A：接口真实 `TruncDate + Count` 聚合，平台记录集中在今天，所以历史上是 0；可以现场新增一条推理让今天的柱子变高来证明联动。

**Q7：并发两个人同时推理会怎样？**
A：预测串行化保证不崩；记录更新按 `record_id` 精确匹配；瓶颈在 CPU，不在数据一致性。

**Q8：数据库为什么用 SQLite？**
A：教学/单机演示够用且零运维；ORM 层已隔离，换 PostgreSQL 只改 settings 和迁移。

**Q9：有没有登录和权限？**
A：当前没有，是明确短板；下一步做 Django 认证 + 按用户隔离记录与费用。**主动承认**比被问出来好。

**Q10：外部网图识别差怎么办？**
A：已定位为分布差异；试过 CLAHE 增强但效果不稳定，已回滚，避免"为演示而演示"；后续方向是数据增广与域适应，而不是在推理端硬调。

**Q11：环形图是识别占比吗？**
A：是数据集类别分布（训练集标注统计），已在标题和脚注标注，避免与在线推理混淆。

**Q12：为什么类别要中英双语？**
A：数据集类别名是英文，界面需要中文可读性；统一映射后推理结果、历史、详情、LLM 输入口径一致。

**Q13：mAP 到底多少？**
A：best.pt 89.7%，末轮 86.2%；不要引用 94.2%，那是早期文案遗留，已修正。

- 不说"支持高并发/高可用/微服务"；
- 不说"实时视频流分析"（实际是上传后离线逐帧）；
- 不说"做了图像增强提升泛化"（CLAHE 已回滚）；

- 不把"数据集类别分布"说成"推理识别占比"；
